# T10 — 带货模板：一档直播一个文件

> 状态：T10 完成。场景包 `examples/scene-packs/livestream-selling.md` release 1.0.0。
> 一档直播一个文件：商品卡、分镜脚本、合规 flag、每 SKU 复盘自动附上。

## 模板结构

场景包 `examples/scene-packs/livestream-selling.md`（v1 BotMRR Markdown，
`botmrr: 1`），两个角色、一个共享房间、一份 playbook 对应一个环节：

- **writer（Livestream Writer，Chief of Staff）** — 写场次文件：商品卡、
  分镜脚本、每 SKU 复盘栏骨架。playbook `session-file`。
- **reviewer（Compliance Reviewer）** — 扫描脚本里的绝对化用语，逐条 flag，
  未清完不许开播。playbook `compliance-check`。
- **房间 `sessions`** — writer + reviewer；口号：一档直播一个文件，未 flag
  的绝对化用语不许开播。
- **routine `after-stream-review`** — 每日 22:00，提醒 writer 给当日场次文件
  的每个 SKU 补一行复盘（售出、收入、下次改什么）；暂停态（`enabledAfterInstall: false`），
  销售数字缺失时只写缺什么，不编数字。
- **技能 `compliance-scan`** — 如何逐行扫脚本、记录行号与严重程度、改写、
  改完重扫；格式照抄 T09 的 `diff-evidence` 技能。

场次文件固定四段，按此顺序：

1. **商品卡** — 商品名、SKU 列表（名称、价格、库存）、最多 3 条卖点。
2. **分镜脚本** — 编号分镜，每镜一个动作加一句口播。
3. **合规 flag** — 每条一行：行号、原文、严重程度；扫描干净时写空。
4. **每 SKU 复盘** — 直播后追加；每 SKU 一行：售出、收入、下次改什么。

校验：场景包通过 `scripts/morde-verify-scene-pack.ts`，上游解析器输出 agents
`writer`/`reviewer`、rooms `sessions`、playbooks `session-file`/`compliance-check`、
routines `after-stream-review`、skills `compliance-scan`。未加 package 格式之外的
自定义字段（见 `docs/morde-scene-pack-mapping.md` §4）。本模板不需要已连接应用，
`requirements.apps` 与 `requirements.capabilities` 均为空数组。

## 合规规则

合门：**有未清合规 flag 的脚本不许开播**，无论问题多小。审查员改完必须重扫，
直到整份扫描干净。

合规检查脚本 `scripts/morde-verify-livestream.ts`，用法：

```sh
node --experimental-strip-types scripts/morde-verify-livestream.ts <场次文件.md>
```

退出码：0 扫描干净；1 发现 flag；2 用法或读文件错误。输出每条 flag 的行号、
命中词、严重程度与原文行，最后汇总计数。

词表（18 条规则，两档严重程度）：

- **严重**：最好、最佳、第一、No.1、全网最低、最低价、100%、顶级、国家级、
  唯一、首选、保证、零风险、绝对、第一名、史无前例、独家。
- **注意**：最 + 程度形容词（最便宜、最划算、最强、最高、最低、最快等）。

两条实现上的取舍：

- **裸字“最”不直接匹配** — “最”也出现在“最近、最后、最终”里，直接匹配
  误报太多；只匹配“最 + 程度形容词”的组合。
- **同一说法只报一条 flag** — 命中位置重叠的规则只保留先出现、更长的那条，
  例如“全网最低价”只报“全网最低”，不连带报“最低价”和“最…”。
- **合规 flag 栏本身不参与扫描** — 标题含“合规”的小节是 flag 清单，引用被
  flag 的原文，不应被重复计入；场次文件其他位置出现词表里的词仍会被 flag。

## 验收

商品：**哈尔斯 HAERS 316不锈钢保温杯 500ml**，日常价 79 元，直播价 49.9 元，
两个 SKU（曜石黑 / 珍珠白，各 200 件），卖点 3 条（316 不锈钢内胆、24 小时
保温保冷、一键弹盖）。

样本文件：

- 含绝对化用语版：`docs/morde-t10-livestream-sample.md` — 分镜 7–9 故意放了
  3 处绝对化用语（“全网最好的保温杯”“全网最低价”“100% 不会漏水”）。
- 改干净版：`docs/morde-t10-livestream-sample-clean.md` — 3 处改成可验证的
  说法（“同价位里保温表现靠前”“直播间专属价 49.9 元”“倒置测试 30 分钟没有渗漏”），
  其余内容不变。

实测结果（真实跑出来的输出）：

```
== 含绝对化用语版 ==
行 29 [严重] “最好” — 7. 逼单 — 面向镜头：“这是全网最好的保温杯。”
行 30 [严重] “全网最低” — 8. 逼单 — 指向库存牌：“今晚全网最低价，错过就没有。”
行 31 [严重] “100%” — 9. 收尾 — 拿起两只杯子：“100% 不会漏水，买回去放心用。”
共 3 处 flag（严重 3，注意 0）
退出码 1

== 改干净版 ==
合规通过，无绝对化用语
退出码 0
```

样本的合规 flag 栏已按脚本输出填入真实行号；复盘栏的销售数字是演示数据
（文件内已注明未真实开播），仅用于验收复盘栏格式。

验收中踩到的两个坑：

1. **重叠规则会重复报** — 第一版对“全网最低价”一次报了 3 条 flag
   （全网最低、最低价、最…），已修成按命中位置去重，一处说法只报一条。
2. **“绝对化用语”这个词本身含“绝对”** — 干净版开头说明里写了“3 处绝对化
   用语”，被扫出 1 条 flag；已改写成“3 处违规表述”。词表是关键词匹配，
   元文本里出现词表里的词一样会被 flag，只有合规 flag 栏例外。

## 诚实说明

- 这次验收是我（agent）按模板手动执行的，**不是服务器上的 Bot 跑的**
  （T05 配对未完成）。
- 合规脚本是关键词匹配：能标出词表里的绝对化用语，但换个说法的夸大
  （例如分镜 3 “明早还是热的”）扫不出来，仍需人工审查员把关；词表也
  不是广告法全文，只覆盖直播口播里最常见的绝对化与承诺性表述。
- 样本商品与价格取自哈尔斯保温杯这一常见直播商品，用于验收模板格式，
  不是真实带货合作，复盘数字是演示数据。
